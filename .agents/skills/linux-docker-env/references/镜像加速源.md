# Docker 镜像加速源：测速、优选与切换

## 为什么不能硬编码镜像源

公共加速地址由不同团队/个人维护，随时可能：

- 限流、限速（高峰期极慢）
- 改域名、停服
- 被 DNS 污染或直接无法访问

因此本仓库的策略是：**每次用之前先测速，用实测最快的；失效自动换。**

## 候选源

| 镜像源 | 特点 |
|---|---|
| `https://docker.1ms.run` | 首选，速度快 |
| `https://hub.rat.dev` | 速度快（302 跳转到真实源，测速脚本已跟随重定向） |
| `https://ccr.ccs.tencentyun.com` | 腾讯云，速度快，可用性好 |
| `https://docker.1panel.live` | 速度慢，但基本可用 |
| `https://docker.shootchat.top` | 能加载，但很慢 |
| `https://docker.xuanyuan.me` | 免费，有限流限速，偶尔不可用 |
| `https://xuanyuan.me` | 轩辕站点，通常不提供 registry 服务，测速会自动淘汰 |

> 实际排名随时间、地区、运营商变化。**以脚本实测结果为准，不要照抄本文表格。**

## 测速原理

### 快速模式（默认，约 20 秒）

对每个源请求 `/v2/`（Docker Registry v2 API 根端点）：

```bash
curl -sL -o /dev/null -w '%{http_code} %{time_connect} %{time_total}' https://<源>/v2/
```

判定：

- `200` / `401` → **在线**（`401` 是正常的，表示需要认证，说明 registry 活着）
- 其它状态码或超时 → 不可用

评分 = `1000/总耗时 + 100/连接耗时`，越大越快。

### 真实拉取模式（--full，约 60 秒）

从**该加速源自己的 token 服务**取匿名 token（各加速源都有自己的 `WWW-Authenticate` realm，不依赖 `auth.docker.io`——后者在部分国内网络不可达），再真实拉取 manifest：

```bash
curl -sL -o /dev/null \
  -H "Authorization: Bearer $TOKEN" \
  -H "Accept: application/vnd.docker.distribution.manifest.list.v2+json,..." \
  -w '%{http_code} %{time_total} %{speed_download}' \
  https://<源>/v2/library/alpine/manifests/latest
```

用实际下载速度（字节/秒）排序，最能反映拉大镜像的真实体验。

实现要点（踩过的坑）：

- **token 与 host 绑定**：跨主机跳转的源（如 `hub.rat.dev` → `docker.1ms.run`）必须用目标主机的 token；
- **curl 跨主机重定向会丢弃 `Authorization` 头**：因此直接请求重定向后的最终 URL，而不是跟随重定向；
- **优先尝试匿名拉取**：部分加速源允许匿名，比带 token 更快。

### 时间预算

脚本有全局预算控制，不会长时间卡住：

```bash
--timeout 8    # 单源超时（默认 8 秒）
--budget 60    # 总预算（默认 60 秒，超出即跳过剩余源）
```

## 常用命令

```bash
# 排名总览（约 20 秒）
bash scripts/test_mirrors.sh

# 真实拉取测速（约 60 秒，更准）
bash scripts/test_mirrors.sh --full

# JSON 输出（便于上层解析）
bash scripts/test_mirrors.sh --json

# 单测一个源
bash scripts/test_mirrors.sh --mirror https://docker.1ms.run

# 临时追加候选源
bash scripts/test_mirrors.sh --extra https://your-mirror.example.com

# 调整超时与总预算
bash scripts/test_mirrors.sh --timeout 5 --budget 30
```

## 自动切换

```bash
# 当前源还可用且排名靠前 → 不动；不可用 → 自动切到最快的
bash scripts/switch_mirror.sh

# 无条件切到当前最快的
bash scripts/switch_mirror.sh --force

# 写入前 3 个可用源（多源容灾，但可能相互拖累）
bash scripts/configure_mirrors.sh --top 3

# 预览将要写入的配置，不实际修改
bash scripts/switch_mirror.sh --test

# 只体检当前配置的源
bash scripts/configure_mirrors.sh --check
```

### 写入流程

1. 测速，拿到按速度排序的可用源列表；
2. 判定是否需要切换（默认：当前源不可用 **或** 排名跌出 TOP 才切）；
3. 备份 `/etc/docker/daemon.json` → `daemon.json.<时间戳>.bak`；
4. 合并写入新的 `registry-mirrors`，**保留原文件其它字段**（`data-root`、`log-driver` 等）；
5. 用 `python3` 校验 JSON 合法性，非法则放弃修改（不动原文件）；
6. `systemctl daemon-reload && systemctl restart docker`；
7. `docker pull hello-world` 验证。

## 手动兜底

自动流程失败时，手动编辑：

```bash
sudo tee /etc/docker/daemon.json >/dev/null <<'EOF'
{
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://ccr.ccs.tencentyun.com"
  ]
}
EOF
sudo systemctl daemon-reload && sudo systemctl restart docker
docker info | grep -A5 "Registry Mirrors"
```

## 全部源都不可用时

1. 确认出网与 DNS：`curl -sI https://registry-1.docker.io/v2/`
2. 确认不是防火墙拦截：`sudo iptables -L -n | grep -i drop`
3. 考虑内网 registry / 自建 Harbor；
4. 离线环境走 `docker load` 导入，见 `离线安装.md`。

## 恢复默认（去掉所有加速源）

```bash
sudo cp /etc/docker/daemon.json /etc/docker/daemon.json.bak.$(date +%s)
sudo tee /etc/docker/daemon.json >/dev/null <<'EOF'
{
  "registry-mirrors": []
}
EOF
sudo systemctl daemon-reload && sudo systemctl restart docker
```
