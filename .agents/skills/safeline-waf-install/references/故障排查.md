# 雷池故障排查

## 实测记录（CentOS 7.9 / 192.168.99.3 完整跑通）

以下为真实环境从零安装的完整记录，skill 已针对这些坑做了适配：

| 阶段 | 遇到的问题 | skill 的处理 |
|---|---|---|
| 1 预检查 | `ssse3=1 avx2=0`（无 AVX2） | 不阻断，仅提示性能下降 |
| 2 python3 | CentOS 7 默认只有 python2.7 | `install_docker.sh` 自动 `yum install python3` |
| 3 轩辕脚本 | 交互菜单 + `read` 遇 EOF 死循环 | `pty_runner.py` 分配伪终端自动应答 |
| 3 轩辕脚本 | 下载 Docker 二进制很慢（~45KB/s） | 后台并行预取 Compose 二进制，节省总耗时 |
| 4 Compose | 轩辕脚本没装上 Compose | `install_compose.sh` 补装（包管理器→RPM→静态二进制） |
| 4 Compose | v2.29+ 在老 CPU 段错误 | 下载后实测 `version`，段错误自动降级版本 |
| 5 校验 | 镜像源探测通过但拉不动镜像 | `test_mirrors.sh --full` 真实拉 manifest 筛选 |
| 6 优选 | daemon.json 合并生成非法 JSON | 改用 python3 合并 + 校验，非法拒绝写入 |
| 装雷池 | 官方脚本报 `STDIN 不是标准的 TTY` | `install_safeline.sh` 内置 pty_runner |
| 装雷池 | 询问安装目录，喂 `1` 报"不是合法的绝对路径" | pty 规则：安装目录回车用默认 `/data/safeline` |
| 收尾 | 官方默认目录是 `/data/safeline` 不是 `/opt/safeline` | verify.sh 已按新目录检查 |

最终结果：7/7 容器 healthy，控制台 `https://<IP>:9443/` 返回 200。

## [ERROR] 运行脚本的方式不对，STDIN 不是标准的 TTY

**最常见的问题。** 官方 `manager.py` 要求 stdin 是标准终端，直接在脚本/管道里跑会报这个错然后退出。

解决：用伪终端执行。skill 的 `install_safeline.sh` 已经内置了 `pty_runner.py`（python3 实现）自动处理：

```bash
python3 scripts/pty_runner.py 'bash -c "$(curl -fsSLk https://waf-ce.chaitin.cn/release/latest/manager.sh)"' /tmp/sl.log
```

手工执行时也可以用 `script`：

```bash
script -qec 'bash -c "$(curl -fsSLk https://waf-ce.chaitin.cn/release/latest/manager.sh)"' /dev/null
```

> 注意：菜单里第二个问题「请输入安装目录」必须回车（用默认 `/data/safeline`），如果喂 `1` 会报 `"1" 不是合法的绝对路径` 并循环重问。

## 提示 "docker compose" 不存在 / 版本过低

```bash
docker compose version      # 需要 v2.0.0 以上
docker-compose version      # 独立二进制同样可以
```

安装方式（选一）：

```bash
# 方式 A：RPM（CentOS 7 推荐，包小速度快）
# 先列包名
curl -fsSL https://mirrors.tencent.com/docker-ce/linux/centos/7/x86_64/stable/Packages/ \
  | grep -o -E 'docker-compose-plugin-[0-9a-zA-Z._-]+\.rpm' | sort -u | tail -1
# 再下载安装
curl -fsSL -O https://mirrors.tencent.com/docker-ce/linux/centos/7/x86_64/stable/Packages/docker-compose-plugin-<版本>.rpm
rpm -ivh --nodeps docker-compose-plugin-<版本>.rpm

# 方式 B：静态二进制（放两个位置都兼容调用方式）
curl -fsSL -o /usr/local/bin/docker-compose \
  https://github.com/docker/compose/releases/download/v2.24.6/docker-compose-linux-x86_64
chmod +x /usr/local/bin/docker-compose
mkdir -p /usr/local/lib/docker/cli-plugins
cp /usr/local/bin/docker-compose /usr/local/lib/docker/cli-plugins/docker-compose
```

> **版本坑**：compose v2.29.x 在部分老 CPU（如 QEMU 虚拟机的 `QEMU Virtual CPU version 2.5+`）上会 **Segmentation fault**。遇到段错误就降到 **v2.24.6** 或更低。

## 脚本提示缺少 python3

官方 `manager.sh` 会检测并尝试用包管理器安装 python3。若发行版不被脚本识别（只覆盖 ubuntu/debian/centos/rhel/fedora/alpine），手动装：

```bash
# Debian/Ubuntu 系
sudo apt-get update && sudo apt-get install -y python3
# RHEL/Rocky/Alma 系
sudo yum install -y python3
```

> CentOS 7 默认是 python2.7，`python3` 需要手动装（`yum install -y python3`）。雷池安装脚本与 pty 应答器都依赖 python3。

## 镜像拉取超时 / 失败

**先测速再配置**，不要硬编码镜像源：

```bash
bash <linux-docker-env>/scripts/test_mirrors.sh --full
bash <linux-docker-env>/scripts/configure_mirrors.sh --force
```

> 重要坑：**`/v2/` 探测通过 ≠ 真能拉镜像**。有些加速源（如 `hub.rat.dev`）探测正常，但实际 pull 时会直连 `registry-1.docker.io` 并超时。必须用 `--full`（真实拉 manifest）筛选。

若仍失败，走官方「离线安装」流程（`references/离线安装.md`）。

雷池官方镜像托管在华为云 SWR：`swr.cn-east-3.myhuaweicloud.com/chaitin-safeline/*`，拉取很快。

## 容器启动后立刻退出

```bash
docker ps -a --filter "name=safeline"
docker logs --tail 100 safeline-mgt
docker logs --tail 100 safeline-detect
```

常见原因：
- 内存不足（检测引擎吃内存，至少 2G，建议 4G）；
- CPU 不支持 ssse3（x86_64 架构）；
- 端口 9443 被占用。

## 9443 端口被占用

```bash
ss -lntp | grep 9443
```

改用其它端口需在雷池容器创建时通过环境变量指定，例如 `SAFELINE_PORT=9444`，或先释放被占端口。

## 忘记管理员密码

```bash
docker exec safeline-mgt resetadmin
```

## 访问 https://<IP>:9443/ 打不开

1. 确认服务在跑：`docker ps | grep safeline`
2. 确认端口监听：`ss -lnt | grep 9443`
3. 放行防火墙：

```bash
# firewalld
sudo firewall-cmd --permanent --add-port=9443/tcp && sudo firewall-cmd --reload
# ufw
sudo ufw allow 9443/tcp
# iptables
sudo iptables -I INPUT -p tcp --dport 9443 -j ACCEPT
```

4. 云服务器还需在**安全组**里放行 9443。

# 停服务（保留数据）
bash docker-compose.yaml down

# 彻底卸载（删除数据，谨慎）
bash docker-compose.yaml down -v
