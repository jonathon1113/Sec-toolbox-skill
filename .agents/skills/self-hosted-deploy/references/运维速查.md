# 运维速查

> 通用命令见文末；雷池与 ARTEX 各自的目录与命令见对应小节。

## 安装目录

| 路径 | 说明 |
|---|---|
| `/data/safeline` | **官方默认安装目录**（安装时询问，留空即用此路径） |
| `/data/safeline/docker-compose.yaml` | 编排文件 |
| `/data/safeline/resources` | 静态资源、证书 |
| `/data/safeline/logs` | 本地日志 |

## 服务启停

```bash
cd /data/safeline

# 启动
docker compose -f /data/safeline/docker-compose.yaml up -d

# 停止
docker compose -f /data/safeline/docker-compose.yaml down

# 重启
docker compose -f /data/safeline/docker-compose.yaml restart

# 查看状态
docker ps --filter "name=safeline"
```

## 端口与网络排查

雷池各容器多用 `host` 网络模式，此时 `docker port <容器>` 返回空属正常，**不能据此判断"没有对外端口"**。
确认实际监听请用：

```bash
ss -lntp | grep -E '9443|65443'
docker inspect safeline-tengine --format '{{.HostConfig.NetworkMode}} {{json .NetworkSettings.Ports}}'
```

- `9443` 由 `docker-proxy` 监听，是控制台端口。
- `65443` 由容器内的 nginx 进程监听，是 tengine 的 HTTP 入口。

## 常用运维命令

```bash
# 实时日志
docker logs -f safeline-mgt
docker logs -f safeline-detect

# 进入容器
docker exec -it safeline-mgt sh

# 重置管理员密码
docker exec safeline-mgt resetadmin

# 资源占用
docker stats --no-stream $(docker ps -q --filter "name=safeline")
```


## 端口

| 端口 | 用途 |
|---|---|
| 9443 | 控制台（默认） |
| 80 / 443 | 业务流量（反代接入的站点走这里） |

## 反向代理接入

在雷池控制台 →「添加应用」中配置：
- 监听端口（通常 80/443）
- 域名
- 上游地址（后端真实服务 IP:端口）
- 上游健康检查（可选）

配置完成后把域名的 DNS 解析指向雷池服务器，并在上游服务器放行来自雷池 IP 的回源流量。

## ARTEX

### 目录

| 路径 | 说明 |
|---|---|
| `/opt/artex` | 代码与配置目录（compose 模式） |
| `/opt/artex/.env` | 环境变量（**含 POSTGRES_PASSWORD，勿提交仓库**） |
| `/opt/artex/skills` | 技能持久化（bind mount） |
| `/opt/artex/data` | 数据持久化（bind mount） |
| `/opt/artex/artex` / `start.sh` | 预编译二进制模式下的程序与守护脚本 |

### 常用命令

```bash
cd /opt/artex

# 状态 / 日志
docker compose ps
docker compose logs -f artex

# 重启 / 停止 / 启动
docker compose restart artex
docker compose down
docker compose up -d

# 取一次性 setup token
docker compose logs artex | grep "Setup token"

# 改了 .env 后必须重建容器（环境变量只在创建时注入）
docker compose up -d --force-recreate artex
```

### 二进制模式

```bash
cd /opt/artex
nohup ./start.sh >artex.log 2>&1 &     # start.sh 是守护脚本，别直接跑 ./artex
tail -f artex.log
```

### 端口与访问

- `8787` 是 Web UI 端口，由 compose 按 `ARTEX_BIND_ADDR` 绑定。
- **`ARTEX_BIND_ADDR=127.0.0.1` 时远程访问不了**，要改 `0.0.0.0` 并 `docker compose up -d` 重建。
- UI 默认只信任本机；走反代时把反代 IP 段写进 `ARTEX_TRUSTED_PROXIES`（CIDR，逗号分隔），否则登录限流会误判 X-Forwarded-For。

## 通用命令

```bash
# 端口占用
ss -lntp | grep -E '9443|8787|65443'

# 容器状态 / 日志
docker ps -a --format '{{.Names}}	{{.Status}}'
docker logs <容器名> --tail 100

# 磁盘占用（镜像与数据）
docker system df
du -sh /data/safeline /opt/artex 2>/dev/null

# 清理（会删数据，操作前确认）
docker system prune -a          # 删未使用的镜像/容器/网络
```

> 🔴 `docker compose down -v` 会删除数据卷（postgres 数据、持久化目录）。执行前必须与用户确认。
